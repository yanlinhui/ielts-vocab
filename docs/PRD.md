> 最后更新：2026-10-16
> 配套文档：[计划文档](./plan.md) · [技术规范](./tech-spec.md)

## 1. 用户与场景

### 1.1 用户

**主要用户：你自己。** 备考雅思，有《雅思词汇真经》这本书，会一点代码。

**潜在用户（二期后）：** 同样在用这本书的朋友。因此数据模型要按多用户设计，但 MVP 不做登录。

### 1.2 典型使用场景

**场景 A：每天早上通勤/早读时背 20 个新词**
打开网页 → 首页显示「今日新词 0/20，待复习 43」→ 点开始 → 一张张过卡片 → 结束时看到今日完成。

**场景 B：晚上复习当天到期的词**
打开网页 → 待复习 43 个 → 过一遍 → 答错的词在本次会话里会再出现一次。

**场景 C：想专门攻克某一章**
去章节列表 → 找到「Chapter 1 自然地理」→ 点进去 → 只背这一章的词。

**场景 D：坐公交车，用手机**
手机浏览器打开同一个地址 → 卡片布局自动适配竖屏 → 可以用手指点翻面和评分。

### 1.3 核心设计原则

1. **一次只做一件事**：学习页一次只显示一个词，不显示其他干扰信息
2. **减少决策成本**：评分按钮只有 4 个，键盘 1-4 直接选
3. **不打断心流**：不弹窗、不二次确认、不要求打字（学习模式下）

## 2. 功能需求

### 2.0 全局导航

四个入口：**今日功课**（首页）/ **章节词汇** / **研习统计** / **研习设置**。当前所在的那一项要标出来（此前几个链接永远长得一样，看不出自己在哪）——桌面侧栏是**整块朱砂底**盖住该项，划过其他项也有一层更暗的橙；窄屏顶栏是一条朱砂下划线（那栏只有一行高，再压底色会把品牌字挤没）。

> **文案是四字，2026-10-16 改的**（原为「今日 / 词库 / 设置」），要的是「不像 App 菜单」——几个词都落在同一套句式里（时间 / 范围 / 方式），且都能一眼看懂：「今日功课」比「今日」多一层「这是要做的活」，「章节词汇」直接说清这一页是 22 章的词，「研习设置」比「设置」书面。没往更生的文言走（如「凡例」——古籍正文前讲体例规则的那部分，语义其实最贴「设置」），导航项认不出来就是失败。
>
> **第四项「研习统计」是同日晚些时候加的**（统计页做完时），排在第三、设置仍在最末——它补的是那套句式里缺的「回顾」那一格。
>
> **页内大标题跟着一起改**（2026-10-16）：`/units` 的 h1 从「词库」改为「章节词汇」，`/settings` 的 h1 从「设置」改为「研习设置」，学习完成页那句「去『词库』挑一个章节加练」和按钮「浏览词库」也一并跟进（改成「章节词汇」「浏览章节词汇」）——**界面里不该再留下「词库」这个没有对应入口的词**。唯一不同名的是首页：它的 h1 是「今天要背的在这儿」，那是句状态描述（有待办 / 已完成两态），不是栏目名。
>
> **同一轮里漏了两处，2026-10-16 补齐**：那轮改的是导航项和完成页文案，**首页空库错误态**（`词库是空的`）和**设置页统计行**（`词库总词数`）没跟上——前者是数据库为空才出现的引导页，平时看不见；后者藏在设置页中段。现在换成「这本书还没有词」和「总词数」（后者与首页那行 `<Stat label="总词数">` 同一个词，不另造说法）。改完 `src/` 目录里已经没有「词库」二字；文档里还留着的都是改名前后经过的记录，不动。

**位置随屏幕宽度变**（2026-10-16 改版）：

| 视口 | 导航位置 |
|---|---|
| ≥1024px | 左侧竖栏，宽 240px，不随页面滚动 |
| <1024px | 顶部横栏（原来的样子） |

**两套导航都是深色的**（近黑 `#202626`，带极淡绿调），和暖白的内容区构成一本书的「书脊 / 内页」两个面。桌面端每个导航项带一个 16px 图标；**窄屏顶部栏既不加图标、也不显示品牌文字块，只留那枚「词」印章**——375px 可用宽度 343.3px，四个字的项每项 80px，再放完整的品牌块（实测 156.76px）远超出去；收内边距、降字号补不上这个缺口，只能从品牌块腾。收起文字块后又加进第四项，于是再把项的左右内边距从 12px 收到 **6px**、项间间隙从 4px 收到 **2px**：**68 × 4 + 2 × 3 = 278px**，加印章 40 = **322px**，375px 下余 21px、360px 下余 6px；320px 视口连印章也藏掉（品牌 span 加 `max-[359px]:hidden`，省 44px）。手机上导航词比图标好认，印章本身也够当标识。

窄屏不做侧边栏是**有实测依据的取舍**：375px 视口下学习卡就占 343.3px，再挖掉一条固定侧栏，长单词和卡片翻转都会被挤坏。手机上维持原样。

**学习页不再收起左侧栏**（2026-10-16 改）。此前桌面端那一页走「沉浸」、整页只剩卡片，撤掉的理由是：背词中途想换个章节加练、或去设置里改口音，只能手打地址栏；而右侧卡片本来就只占 768px，让出 240px 不改变它的宽度。撤掉后学习页的排布与其余三页完全一致。

> **连带的一处判定**：`/study` 不属于四个入口中的任何一个，不收侧栏之后就会出现「几项全暗」——而标出当前页正是导航改版一直在做的事。但学习页有**两个入口**，归属得看来源：首页点「开始」进来的（`/study`）算**今日功课**（它是首页那条动线的进行状态，不是并列的板块），从章节词汇点某一章进来的（`/study?unit=N`）算**章节词汇**。见 [tech-spec.md 11.13](./tech-spec.md)。

> 实现和验证见 [tech-spec.md 11.7](./tech-spec.md) 和 [11.8](./tech-spec.md)。

### 2.1 首页

**目的**：让用户打开就知道「我现在该干什么」。

**显示内容**：

| 元素 | 说明 |
|---|---|
| 今日进度 | 「新词 5/20」走**答题卡式方格**（一格一词，涂满即完成）+「复习 12/43」走细进度条 |
| 开始按钮 | 主视觉按钮。没有待办时显示「今日任务已完成 🎉」 |
| 连续打卡天数 | 大号数字带「天」单位（单位小一半、不加粗、走次要色），下方是标签「连续打卡天数」（三格同排版、同颜色、同一个字号） |
| 累计数据 | 已掌握词数 / 总词数 |
| 每日一句 | 按日期确定性选一条书里的例句，中英对照 + 章节出处 |
| 学习记录 | 近 16 周的打卡热力图 + 一句文字摘要（排在页面最底，收尾） |

> **「浏览词库 / 设置」两个快捷入口已删掉**（2026-10-16，用户要求）。导航栏本来就有这两个入口（现名「章节词汇」「研习设置」），页面里再摆一份是重复的。
>
> 首页曾经还有一张「雅思核心词 + 词汇维度估算 band」的卡，**同日也按用户要求删掉了**。它的配套代码（`TodayStats` 的两个雅思维度字段、`estimateIeltsBand` 的档位表）一并撤除，见 [tech-spec.md 第 6 节](./tech-spec.md)。词卡上的「雅思」小印不受影响，仍在。

**交互**：
- 点「开始」→ 进入学习页，队列 = 今日新词配额 + 所有到期复习词
- 今日无待办时，按钮变为「额外加练」，点了进入自由练习（不计入统计）

**边界情况**：

| 情况 | 表现 |
|---|---|
| 首次打开，没有任何进度 | 显示引导：「还没开始，点下面按钮背第一个单元」 |
| 今日新词配额已满但还有复习 | 按钮文案变为「继续复习（43）」 |
| 全部完成 | 显示完成态 + 明日预计复习量 |
| 词表未导入（数据库为空） | 显示「这本书还没有词」+ 引导去运行导入脚本 |

### 2.2 学习 / 复习页（核心页面）

**目的**：这是用户 90% 时间停留的页面。**必须做到无摩擦。**

**卡片状态机**：

```
         ┌──────────────┐
         │  正面（未翻）  │  显示：英文单词 + 喇叭按钮
         └──────┬───────┘
                │ 点击卡片 / 按空格
                ▼
         ┌──────────────┐
         │  背面（已翻）  │  显示：音标 + 词性 + 中文释义 + 出处单元
         └──────┬───────┘
                │ 点击评分按钮 / 按 1-4
                ▼
         ┌──────────────┐
         │   下一个词     │
         └──────────────┘
```

**正面**：

- 大号英文单词，居中
- 喇叭图标按钮，点击朗读（**不翻面**，避免误触）；也可以随时按 `S` 键重听
- **每逢卡片转到正面（单词那面）就自动朗读一遍**（默认开，卡片下方的「自动发音」开关可随手关掉，设置页有同一个开关）——包括换到新词时、以及从背面翻回正面时；翻到背面看释义时不读
- 底部提示：「点击卡片查看释义」

**背面**：

- 单词（小一号，仍在顶部，便于对照）
- 音标（一条。ECDICT 只提供一份音标，不分英美，已合并成一个字段）
- 词性（`n.` / `v.` / `adj.`，多个则并列）
- 中文释义
- `[搭]` 搭配
- `[例]` 例句（英文 + 中文翻译，每条带朗读按钮）
- 词根词源 / 派生 / 文化背景
- 所属章节（如 `Chapter 1 自然地理`）
- 底部四个评分按钮

> **背面一次性铺开全部内容，没有折叠、不用点开。**（2026-10-15 调整，原设计是四个默认折叠的 `<details>`）
>
> **卡片内不滚、字号不缩——装不下就让整页滚。**（2026-10-16 方向反转，此前两轮追的「一屏全显」已作废）之前先给卡片限高让正文自己滚，再改成正文字号逐档自适应（17px→11.22px）把内容压进一屏；用户实机反馈**字太小**（矮窗口下正文被压到 11.22px），要求「字号大一点、放不下就整页滚」。现在正文字号固定 **18px**（例句 0.88em、中文翻译 0.82em 等比跟着走），矮窗口那套紧凑尺寸一并删除。长词（如 `disaster` 背面 732px）在 1280×800 下整页溢出 121px、375×812 下 215px——这是接受的代价，不是缺陷。
>
> 版面仍是「单词和来源钉在卡片顶部、四个评分按钮钉在底部」，但**高度不再受约束**，卡片按内容自然撑开。正面卡片恒为一屏内的矮卡（实测 320px），不会被背面撑开——单词和「点击卡片查看释义」始终落在首屏。换词时页面自动回到顶部。点正文区空白处翻回正面。
>
> ⚠️ 例句/搭配/词根是**书中原创内容**，不是 ECDICT 来的。见 [plan.md 第 6 节](./plan.md) 的版权说明。

**四个评分按钮**（对应 FSRS 的 4 档 rating）：

| 按钮 | 键盘 | 含义 | 用户该怎么理解 |
|---|---|---|---|
| 忘了 | `1` | Again | 完全没想起来，或想错了 |
| 困难 | `2` | Hard | 想起来了，但很费劲、犹豫很久 |
| 一般 | `3` | Good | 正常想起来了。**最常用的一档** |
| 简单 | `4` | Easy | 秒答，毫不费力 |

> **设计要点**：必须让用户理解「这个评分会影响下次什么时候再见到这个词」。所以在首次使用时给一个简短提示，并在评分按钮下方显示「下次：3 天后」这样的预览——**这是让用户建立正确评分习惯的关键**，否则所有人都会无脑点「一般」，FSRS 就退化成固定间隔了。

**进度显示**：顶部细进度条 + 「12 / 43」。

**本次会话内的重复机制**：
- 新词答「忘了」→ 在**本次会话内**稍后（约 1~10 分钟后）再次出现
- 已进入复习态的词答「忘了」→ 同样本次会话内再现
- 这样「忘了的词」当天就能再过一遍，而不是等到明天

**队列顺序**：先复习到期旧词，再学新词。（旧词不复习会越积越多，必须优先）

**退出**：任何时候可以退出，进度已实时保存。**不做"确定要退出吗"的弹窗**。卡片下方那一行右侧是一个「退出」按钮（描边样式、和左边的自动发音开关同高），紧挨它的左边写着「进度已实时保存」——把所有顾虑先答掉，用户才敢直接点走；这句话不能只放进悬停提示，手机上悬停不出来。

**边界情况**：

| 情况 | 表现 |
|---|---|
| 队列抽干 | 显示完成页：本次背了 N 个，正确率 X%，明日预计复习 Y 个 |
| 章节专项进门就空 | 显示「第 N 章 XX 已经学完」，主按钮改为「浏览章节词汇」（挑下一章） |
| 词条缺音标/释义 | 字段留空不显示占位符，不报错（数据质量问题不该暴露给用户） |
| 浏览器不支持 TTS | 喇叭按钮置灰 + tooltip 说明（不弹窗） |
| 用户中途刷新页面 | 重新进入，队列重新计算（已评分的词不会重复出现） |

### 2.3 章节列表页

**目的**：让你看见整本书的全局，并能单独攻克某个章节。

**显示**：直接列出 **22 个主题 Chapter**——这本书就是 22 个平级的主题章节，**没有「核心词汇 / 阅读词汇 / 听力词汇」这种大板块**（原计划的推测是错的，已由步骤 0 实测推翻，见 [plan.md 3.3](./plan.md)）。

建议按「已学比例」排序，让你一眼看到哪章还没碰过。

**每个章节显示**：

- 章节名（如 `Chapter 1 自然地理`）
- **学习进度条**：已学 / 总数
- **两个数字**：`已学 N · 掌握 M / 总词数`

> **为什么是两个数（2026-10-16 修）**：此前那栏只有一个数、显示的是「已掌握 / 总词数」，判据 `state === "review" && scheduledDays >= 21`——复习间隔要拉到 21 天以上才算。用户报「学完了进度没更新到章节词汇页」，查完发现**进度一行没丢**（每评一次分就落库），是**指标语义和预期对不上**：刚学完的词稳定度只有几天，这个数本来就不会动；能反映「学过」的只有下面那条进度条，而它按比例画——第 2 章 124 个词，学 3 个 = 2.4%，肉眼看不出来。实测佐证：第 1 章真实有 24 个词学过，那栏却只显示 `1 / 233`。
>
> 现在两个数并排：**「已学」用正文墨色**（它是随时在动的那个），**「掌握」用次要色**（21 天才动一次），一眼分得出谁在涨。页面底部那行小字也重写了，把两个口径说清。
>
> 排查中洗清的两条**不是**原因：Next 的路由缓存 / `<Link>` 预取（客户端导航与硬刷新都拿到新值），以及**浏览器后退键**——后退看到的是 bfcache（前进后退缓存）里离开时的整页快照，任何网站都如此，不是本项目的问题。

**交互**：点击章节 → 进入该章节的专项学习（只背这一章的词）

> **专项模式给的是「这一章里还没学过的词」，不受每日配额约束**（2026-10-16 修了两轮）。此前它虽然只取这一章的词，但取数仍走首页那条每日动线，「每日新词上限」和「今天到期的才拿」两条都还在——于是第 1 章 233 个词只能进 3 个，配额用光时甚至一个词进不去、直接弹「今天没有待学的词了」。改成整章给全之后又冒出第二个问题：**学过的词也在队列里，每次进来都从第 1 个词重排**，用户会以为进度没保存。现在按书序只给还没学过的，再点进来就是接着上次学；整章学完后点进去显示「这一章已经学完」。
>
> **这一章的复习不在这里做**——学过、该复习的词由「今日功课」按到期时间给，这样「每日复习上限」（防积压崩盘）不会被专项模式绕开。见 [tech-spec.md 6.1](./tech-spec.md)。

> **版式（2026-10-16 改版）**：排成**书末目录**的样子——一行一章，上下各一道通栏细线、条目之间发丝线，章节号用衬线墨绿，章名与右边那组数字之间用点线 leader 连起来。改版前是 22 张各自带边框的卡片纵向堆叠，堆下来像看板而不像书；书里的目录本来就没有一圈框。
>
> 375px 下这组数字实测宽 119px、单行不折、整页横向溢出为 0（右边的点线 leader 是 `flex-1`，随宽度收缩吸收差额）。

**边界情况**：

| 情况 | 表现 |
|---|---|
| 词表未导入（数据库为空） | 页面显示引导去运行导入脚本 |
| 某章节词数为 0 | 不显示该章节（数据异常） |

### 2.4 设置

| 设置项 | 类型 | 默认 | 范围 | 说明 |
|---|---|---|---|---|
| 每日新词数 | 滑块 | 20 | 5–200 | 影响每天分配多少新词 |
| 每日复习上限 | 滑块 | 200 | 20–999 | 防止某天积压过多导致崩盘 |
| 发音口音 | 单选 | 英式 | 英式/美式 | 挑音色的首选口音。**只在本地音色里挑**——系统没装对应口音的本地音色时会退回别的本地英文音色（中文版 Windows 常没有本地英式），口音可能不准，但**不走网络、起读快**。见 [tech-spec.md 5.6](./tech-spec.md) |
| 自动发音 | 开关 | **开** | — | 卡片显示正面（单词那面）时朗读，翻回正面会重读；学习页的卡片下方也有同一个开关 |

**边界情况**：修改每日新词数**不回溯影响已有的调度**，只影响未来的新词分配。这一点要在 UI 上提示用户。

### 2.5 统计页 `/stats`（阶段三 · 2026-10-16 已实现）

入口是导航第三项「研习统计」。**四页里唯一一个纯回顾的页面**——不产生待办、不写库、一个交互都没有，数据全部服务端直查（**不建 API 路由**，其余四页也都没有）。窗口固定**近 30 天**，不用热力图那 16 周：112 列在 375px 下每列不足 3px，会糊成一片；30 列约 11px/列，和热力图的方格同档。

| 模块 | 实现 |
|---|---|
| 概览三格 | 近 30 天作答次数 / 正确率 / 已掌握（沿用首页那套 `<Stat>`，同排版同字号） |
| 每日学习量 | 近 30 天**堆叠柱**：复习在下（墨绿）、新学在上（朱砂）。柱高按窗口内最大值归一 |
| 正确率 | 近 30 天**柱列**（不是折线，理由见下），柱高即当天正确率、满格 100% |
| 词汇状态分布 | **横向堆叠条两条**：上条是「全书尺度」（未学 / 已学），下条是「已学内部构成」（已掌握 / 复习中 / 重学中 / 学习中） |
| 老忘的词 Top 20 | 按答「忘了」的次数排，列词 + 释义 + 章节出处 + `忘 N · 共 M`。盘点用，**每行不给单独跳转**；底部一条「集中攻克这 N 个」进错词本（见 2.6） |
| ~~打卡热力图~~ | ✅ **已提前到首页**（2026-10-16）。近 16 周、零 JS、按本地日分组，见 [tech-spec.md 12.2](./tech-spec.md)。**统计页不用再做这一块** |

**三处与原计划的出入，都是实测逼出来的：**

1. **正确率画柱列、不画折线。** 原写的是「正确率曲线 · 折线图」。但一条 `<polyline>` 是一条连续路径——30 天窗口里只有 2 天有日志，其余 28 天会被折线直接连起来，**视觉上等于宣称那几天的正确率是插值出来的，那是撒谎**。柱子则让「这天没学」天然表现为没有柱子，不需要任何特判。
2. **「老忘的词」改按 `ReviewLog` 里 `rating = 1`（忘了）的次数排，不用 `lapses`。** 实测 2026-10-16：27 行 `UserWordProgress` 里 `lapses` **全为 0**——它要卡片**进入复习态之后**再答「忘了」才累加，而现在答错都发生在初次学习步长里，不算 lapse，按原口径这张表是空的。以后卡片进入长间隔，`lapses` 会自然长起来，届时再考虑把两个信号合起来。
3. **状态分布画两条、不画一条。** 原写的是「新词 / 学习中 / 复习中 / 已掌握 的饼图」。全书 3580 个词里只学了 27 个（0.8%），五段挤在一条上、学过的四段加起来不到 3px，全糊成一根线。拆成两条之后，上面那条传达「路还有多长」，下面那条才读得出「学过的这些现在都在什么状态」。

**四块口径**（原先只有文字描述、这轮落定）：

| 口径 | 定义 | 依据 |
|---|---|---|
| 正确率 | 当日 `ReviewLog` 中 `rating >= 3`（一般 / 简单）的占比 | 沿用学习页已有的「记住了」判据，不另造 |
| 已掌握 | `state === "review" && scheduledDays >= 21` | Anki 对「成熟卡片」的定义，统一走 `isMastered()` |
| 新学 / 复习 | 新学 = 进度行的创建日落在当天；复习 = 当天流水里进度行是**更早**创建的 | 沿用首页那条「新词当天被反复提问不算复习」的语义 |
| 时间窗 | 一律近 30 天 | 375px 下每列约 11px，与热力图方格同档 |

> ~~**「老忘的词」不做「点击进入专项复习」。**~~ ✅ **2026-10-16 已由错词本承接**（见 2.6）。当初留这个口子，是因为它需要一个**单词级队列**（`buildSession` 当时只有「每日动线」和「整章专项」两种），而「把一批老忘的词集中攻克」正是阶段三里**错词本**那一项的核心，现在做会和它重复、还得改两遍。**实现和当初的预判一模一样**：给 `buildSession` 加一次 `wordIds` 过滤，统计页和错词本共用同一套排序。**逐词跳转仍然不做**——要的是批次，不是一个个点进去。

> **空数据时不能撒谎。** 没有作答的日子正确率**不画柱**（而不是画一根 0% 的矮柱）；有效数据点不足 2 天时只出一句文字摘要、不画图；所有归一化分母都有除零守卫。库里现在只有 2 天数据，这些分支一定会走到。

### 2.6 错词本（阶段三）

**一句话**：把历史上答「忘了」最多的那些词，单独拎出来练一轮。**与「今日功课」完全独立**——不占每日新词 / 复习配额，也不管这些词今天到没到期。

**入口两处**（导航里**没有**第五项，理由见下）：

| 从哪进 | 长什么样 |
|---|---|
| 研习统计 →「老忘的词」底部 | 「集中攻克这 N 个」 |
| 学习页 →「今天没有待学的词」空态 | 按钮下方一行文字链接「去错词本攻克老忘的词」 |

**规则**：

| 项 | 取值 | 为什么 |
|---|---|---|
| 一次给多少词 | **前 20**，与统计页「老忘的词」**同一份名单** | 会话长度可控；两处数字永远一致 |
| 排序 | 答「忘了」次数降序 | 与统计页同一套排序，错词本不重新发明口径 |
| 已掌握的词 | **不排除** | 这一栏看的是历史上忘过多少次，不看现在还记不记得；已掌握的词再练一遍无害 |
| 地址形态 | `/study?weak=1` | 短、稳定；**不把 20 个 `wordId` 塞进 query**——地址会长得没法看，且名单一变地址就失效 |
| 与 `unit` 同时出现 | **`unit` 优先** | `/study?unit=3&weak=1` 走章节，不会变成错词本。避免一条被手改过的地址在两种模式间摇摆 |
| 侧栏高亮 | 「研习统计」 | 从统计页进来的，与 `/study?unit=N` 亮「章节词汇」同类 |

**导航为什么没有第五项**：窄屏顶栏的宽度预算已经用满了——四项加印章是 322px，375px 屏只剩 21px，**再加一项要溢出 49px**，连 320px 的兜底（藏印章）都救不回来（省完仍差 60px）。所以错词本从既有点位进，不做成并列的第五个板块。

**空态**：一个「忘了」都还没答过时，页面显示「错词本现在是空的」，给「看研习统计」+「回首页」两条去路。

### 2.7 拼写 / 听写模式（2026-10-16 已实现）

**两种子模式，页内切换**：

1. **看中文写英文**（默认）：显示中文释义 → 敲出单词 → 比对
2. **听写**：播放发音 → 敲出单词 → 比对

默认取前者而不是听写：它**不依赖浏览器 TTS**，一进来就能用；听写那一档在 `speechSynthesis` 不可用时置灰。切换会清空输入与上一次的比对结果，不让两个模式串台。

**考哪些词**：**已经学过的词**（有进度行的），一个没学过的不给——拼写是检验不是初学，没见过的词第一题就写不出来。可选地按章节收窄成「第 N 章里**学过**的词」。**不看到期时间、不吃每日新词/复习配额**——这两个是首页那条动线「每天固定喂一点」的规则。

| 从哪进 | 长什么样 |
|---|---|
| 首页 → 主按钮下方 | 「拼写练习（N 个学过的词）」→ `/study?spell=1` |
| 章节页 → 学过词的章节行下 | 「拼写检验这一章（N 个）」→ `/study?unit=N&spell=1` |

两处都做成**文字链接而不是第二个按钮**：主按钮是「今天该干的事」，拼写是加练，主次得分得清。

**比对规则**（关键设计）：

- **不是简单判对错**，而是**逐字符比对并标出错误位置**
- 例：正确答案 `environment`，用户输入 `enviroment`
  → 逐字符铺开，漏掉的那个 `n` 标红加下划线，提示「**第 7 个字母漏了**」
- 这样才能知道是**哪个位置**没记牢，而不是笼统的"错了"

> ⚠️ **2026-10-16 更正一处笔误**：这一节原先写的例子是「第 8 个字母漏了」，但 `environment`(11 个字符) → `enviroment`(10 个) 唯一的单步删除解是删第 **7** 位的 `n`，它自己标红的位置（`enviro**n**ment`）也正是第 7 个——原句那个数字是笔误。实现按第 7 位给，`tests/spelling.test.ts` 里有断言锁着。
>
> 同一节连带记下**为什么用编辑距离而不是最长公共子序列（LCS）**：`environment` 打成 `environmunt` 时，LCS 会判成「多了 u、漏了 e」，而用户实际是**第 9 个字母写错了**——这一节要的正是「标出哪个位置没记牢」，只有带替换的编辑距离说得准。完整论证见 `tech-spec.md` 第 14 节。

**判定标准**：**完全一致才算对**。判等前只做两下归一化——去首尾空白、转小写（那是打字失误，不是没记住）；**词组内部的空格与连字符不归一化**，`in spite of` 里那个空格、`well-known` 里那个连字符本身就是要记住的一部分，抹掉等于放水。

| 结果 | 记哪档 |
|---|---|
| 拼对 | **4「简单」**——能默写出来说明掌握得牢，间隔拉长 |
| 拼错 | **1「忘了」** |

答错时**不立刻落库**：先展示正确答案和逐字符高亮，让人看清错在哪，点「下一个」才记 1——否则第一次回车就等于既提交又落库，卡片已经排回队尾了，错在哪儿都没看见。**结果态的「下一个」自己会接住焦点**（2026-10-16），所以**回车和点它等价**：第一次回车提交答案、看清之后第二次回车才过题，两次是分开的，那层缓冲还在。（此前焦点在这时会掉到 `<body>`，回车管不管用全看浏览器自发的焦点处理，各浏览器不一致——现在是显式实现的。）拼错的词和错词本一样会在**本次会话内**再出现一次（评分后按 FSRS 的 `1m/10m` 步长排回队尾）。

**统计口径**：拼写练习算一次真实作答，落 `ReviewLog` 和 `UserWordProgress`，**不新增「模式」字段**。代价是统计页会把拼写算进「新学 / 复习」——这是可接受的，要区分得动数据模型，不划算。

| 维度 | 要求 |
|---|---|
| **响应速度** | 翻面、评分必须**瞬时**（本地数据，无网络请求）。任何超过 100ms 的卡顿都不可接受 |
| **移动端** | 375px 宽度下可用，卡片和评分按钮要适合手指点击（≥44px 触控区） |

## 3.1 视觉定位

界面走**「深色书脊 + 暖白内页」**：近黑的左侧栏（书脊 / 封皮）+ 暖白的内容区（内页）+ 墨色正文 + 深墨绿强调。目标是让人打开就像翻开一本装帧讲究的书，而不是一个 SaaS 面板——两个面的对比就是「书脊挨着内页」的那道硬边界。

三条具体取向：

- **衬线只用在标题性位置**（页面 h1、卡片 headword、章节号、统计大数字）。正文——释义、例句、中文翻译——保持系统无衬线：宋体在 18px 屏幕上笔画偏细，一天盯几十张卡不耐久读。**唯一的新增例外是首页「每日一句」的引文**（2026-10-16）：它是装饰性引文、不承载久读负担，而中文衬线在短段落上正是书卷气的来源。
- **不用阴影**。层次靠「底色差 + 一条细线」做，纸书没有投影。注意卡片填色和内容底只差 **1.05:1**，轮廓基本全靠那条细线——这是有意的，参考图也是如此。
- **圆角 10px**（卡片）。此前为「书卷感」用的是 6px，这一轮放大一档往参考图靠；书卷感改由「深色书脊 + 暖白内页」那组面对比承担。

**朱砂与墨绿的分工基本不变**：朱砂只做标记（印章、侧栏当前页的覆盖块、新词进度），墨绿只做结构（章节号、主按钮、卡片区块竖线）。朱砂对暖白底只有 4.31:1，够图形元素不够 14px 正文——**唯一的例外是侧栏选中块**，它用的是压暗 10% 的朱砂 `#b84a1f`，压 rail-ink 文字实测 4.65:1，是过了线的。（首页「连续打卡」数字 2026-10-16 从朱砂改回墨色：它和旁边两格是并排的一组，单独染色会让它们看着不像一组。）

**品牌字标是「印章 + 书名」**：朱砂方块里刻一个「词」字，右边中文书名，书名下面一行 `IELTS VOCABULARY`（10px 全大写、拉开字距）。英文那行纯粹是版式补充——书脊上总要有一行拉丁字母压住版面，它不承载信息，所以取直译而不是把「真经」也译出来。

只做浅色、不做深色模式（深色只在侧栏，是固定版式，不是主题切换）。完整色板、对比度实测和字体方案的论证见 [tech-spec.md 第 11 节](./tech-spec.md)，最新一轮见 11.8。
