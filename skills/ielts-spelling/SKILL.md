# 拼写（`/spelling` + `spelling.ts` + `SpellSession.tsx`）

## 链路

```
/spelling[?unit=N]  →  buildSession({ spell: true, unitId })
                    →  StudySession（spell 模式）
                    →  SpellSession（出题、收答案、比对）
                    →  onRate(4 | 1)
                    →  POST /api/review  →  submitRating
```

**拼写没有自己的提交逻辑。** 题面组件是受控的：题目从 `item` 来，结果从 `onRate` 走。队列消费、评分提交、答错重排回队尾、进度条、退出，全在 `StudySession` 里。改拼写时不要绕过这条链路另起一套。

## 队列规则

- 取**学过**的词（有 `UserWordProgress` 行），不看到期时间、不吃每日配额
- 按 `dueAt` 升序，最多 50 个
- `?unit=N` 只保留该章
- 用真实进度行，不发空卡

`dueAt` 升序是刻意的：刚学完的新词 `dueAt` 就在几分钟后，天然落在队首，正好接住“学完 20 个新词立刻回头默写”。换成 `lastReviewAt` 升序会把这批沉到队尾。

## 评分档位是定死的

- 拼对 → `4`（简单）
- 拼错 → `1`（忘了）

不给用户选。拼对说明能默写出来，间隔该拉长；拼错就是没写出来。中间两档在这里没有语义——“拼得很费劲”不是一个可观测状态。

答错不进立即提交：先停在结果态让用户看清错在哪，点“下一个”（或回车）才落库。答对直接过，因为拼对了没什么可看的。

## 比对算法（`src/lib/spelling.ts`）

纯函数、零依赖、不碰数据库，客户端可 import。UI 只消费 `diffSpelling()` 的返回值，**不自己判对错**。

### 归一化只做两件事

```ts
s.trim().toLowerCase()
```

- 大小写和首尾空格是打字失误，不是“没记住”
- **不**动内部空格和连字符。`in spite of` 的空格、`up-to-date` 的连字符本身就是要记住的一部分，抹掉等于放水

### 用编辑距离，不用最长公共子序列

`environment` 打成 `environmunt`：

- LCS 只能说“多了 u、漏了 e”
- 带替换的 Levenshtein 能说“第 9 个字母写错了”

PRD 2.7 要的是“标出哪个位置没记牢”，只有替换操作能表达这件事。

### 回溯优先级（顺序不能改）

从 DP 右下角往左上走：

1. **同字对角平局时，先判“多敲”**：`same && dp[i][j] === dp[i][j-1] + 1`
   `environmentt` 应报“第 12 个位置多敲了 t”，而不是第 11 个——第 11 位本来就是 t
2. **否则对角优先**：能算一次替换，就不要拆成“一漏一多”
3. **剩下才是漏**

第 1 条必须带 `same` 条件。`ab` vs `ba` 和替换平局时，替换更贴切——那是两个字母写反了，不该报成“漏一个、多一个”。

### 文案规则

- 0 处差异：`拼对了`
- 1 处：给**精确位置**（1-based，按正确词计位）
  - `第 8 个字母漏了`
  - `第 9 个字母写成了「u」，应该是「e」`
  - `第 12 个位置多敲了「t」`
- 多处：退回汇总，`漏了 2 个、写错 1 个字母`。“第 3、7、11 个都错了”比错本身还费劲

`extra` 没有对应的正确字符，位置取“插在第几个之前”。结果态里逐字符铺开，红色只标“漏掉的字母”和“写错的位置”；多敲的字母不进那一行，只在句子里点名。

### 不要做的事

- 不要在 UI 里重新比较 `typed === headword` 来覆盖 `ok`
- 不要加“忽略英美拼写”之类的隐式宽容，除非先改 PRD 口径
- 不要把内部空格/连字符归一化掉
- 不要引入第三方 diff 库，词最长二十来个字符，O(n·m) 足够

## 交互约定（`SpellSession.tsx`）

### 两个子模式

- **看中文写英文**（默认）：不依赖 TTS，哪儿都能用
- **听写**：只出声、不给文字线索。切进去时念一遍

⚠️ iOS Safari 要求朗读由用户手势触发，进题时那句可能被忽略。所以题面里的喇叭按钮是**兜底**，不是装饰，不能省。浏览器不支持语音合成时“听写”这一格禁用。

切换子模式要清空输入和比对结果，否则切过去是上一种模式的残留。

### 输入框

`autoCapitalize="off"`、`autoCorrect="off"`、`spellCheck={false}` 全关。手机键盘的自动首字母大写和“智能纠错”会替用户改答案，那这个练习就白做了。

### 焦点

- 换题时把焦点放进输入框（靠 `StudySession` 用 `wordId + 已作答数` 当 key，换题即重建组件）
- 答错进入结果态时，原来的 `<form>` 被卸载，焦点会掉到 `<body>`，而焦点在 body 上按回车什么都不会发生。所以必须显式把焦点交给“下一个”按钮——**按钮获得焦点时回车激活它，是规范保证的行为**，跨浏览器一致
- 焦点掉到 body 还会让键盘用户按 Tab 从页面开头重来

### 听写模式不提快捷键

输入框占着键盘，`S` 会被当成字母打进去。

## 页面层（`src/app/(app)/spelling/page.tsx`）

- 范围 chip 只列**有学过词**的章；一个词都没学过的章点进去必定空队列
- 范围 chip 是纯 `<Link>`，零 JS
- **`StudySession` 的 key 必须随 `unit` 变**（`key={validUnitId ?? "all"}`）。点 chip 是“同一路径只换 query”的客户端导航，组件实例不会卸载，而 `queue` 是 `useState(initialQueue)` 只在挂载时读一次。不换 key，服务端送来的新队列会被丢掉，页面继续显示上一批词，而且越答越少，看着像“这一章真的只有这么几个词”
- `/study` 没有这个问题：换章是从 `/units` 进来的，是一次真正的挂载

新旧路径：`/study?spell=1` 会 302 到 `/spelling`，带 `unit` 一并带过去。

## 验证

`npm test`，`tests/spelling.test.ts`（17 条）覆盖：完全正确 / 大小写 / 首尾空格、单字母替换、漏字母、多字母、字母对调、词组内部空格、连续多敲的位置归属。

改回溯分支后至少手动验证三个例子：`environmentt`、`environmunt`、`ab` vs `ba`。测试绿了不代表分支被测到，做一次变异检查：故意改坏一个条件，确认有测试变红。

浏览器里：

1. 拼对直接进下一题；拼错停在结果态，错的位置标红
2. 答错后回车能过（焦点在“下一个”上）
3. 切“听写”，进题出声；点喇叭能重听
4. 点章节 chip，队列真的换成该章的词（不是上一批剩下的）
5. 一个词都没学过的章不出现在 chip 里
6. 手机键盘不自动首字母大写
